# 短故事形态（1.5-8 万字单本完结）

> 长篇引擎的**并行形态**。当用户要写「短故事 / 短篇 / 番茄短故事 / 投稿变现」时读本文件。
> 实测跑通：一部 10 章 / 约 1.97 万字的五单元民俗规则怪谈短故事，全篇 P0=0。

## 一、形态对比（先判断走哪条）

| 维度 | 长篇连载 | **短故事** |
| --- | --- | --- |
| 篇幅 | 十万字-数百万字 | **6000-80000 字，单本完结** |
| 分段 | 卷 → 批次 → 章 | **批次 = 全篇**（通常 1-2 批跑完） |
| 章长 | 2000 字 | **1600-2400 字**（建议 1800 左右） |
| 章数 | 数百上千 | **8-20 章** |
| 签约 | 2万/5万/8万三次机会，失败即永久失去 | **满 6000 字即自动开放申请，无次数限制** |
| 全勤/年度奖 | 有 | **没有**（新人最大误区） |
| 流量长尾 | 完结后持续吃听读 | **上线 1-2 个月即结束** |
| 最大出口 | 版权 | **短剧/漫剧改编**（改编率超 40%） |

**判定规则**：用户提到「番茄 / 短故事 / 短篇 / 投稿赚钱 / 改编短剧」→ 走本形态。

## 二、短篇的结构纪律（比长篇更严）

短篇没有铺垫空间，**前 3 章就是全部身家**。

### 五单元制（推荐骨架）

10 章拆成 5 个单元，每单元 2 章。好处：
1. **完读率友好**——读者从任意一章进来都读得懂
2. **天然适配短剧**——每个单元就是一个独立短剧单元
3. **写作有节拍**——单元 = 埋 → 收

```
单元一(1-2) 埋规则与异常
单元二(3-4) 破禁 → 第一次兑现
单元三(5-6) 危机落到主角身上
单元四(7-8) 抉择 → 情感兑付
单元五(9-10) 解谜 → 收束
```

### 情绪纪律（沿用引擎通用规则，但样本更少）

- **连续「压」不超过 2 章**——10 章里连压 3 章就是 30%，读者跑光
- **爽点间隔不超过 8 章**——10 章的书等于**必须有 2-3 次明确兑现**
- 第 3 章必须有微爽（"主角动了手"），第 4 章必须完整兑现

⚠️ **实测踩坑**：给带"秘辛/得法"的章节打标签时，写成 `压(秘辛:...)` 会被脚本判定为**纯压**（判定逻辑是"含压 且 不含爽/燃"）。带实质推进的章节必须标 `压+爽(得法:...)` 才算兑现。同一章在情绪曲线上漏标一次，就会连成 3 连压误报 P0。

### 钩子轮换（不得连用 3 章同形状）

10 章实测可行序列：
```
信息炸 → 动作悬停 → 对白悬停 → 信息炸 → 对白悬停 → 抉择式 → 登场式 → 对白悬停 → 短句留白 → 短句留白
```
⚠️ 结尾两级用同一个形状是**刻意的**（收束的呼吸感），但**开头绝不能**。

## 三、伏笔管理（短篇规则不同）

- **最长跨 3 章必须回收**（长篇是跨 2 卷）
- 全篇结束**必须 100% 回收**，一条不留
- 实测一部 15 条伏笔（F01-F15）的短故事，全部回收

**收尾自检脚本**（比人工靠得住）：
```python
# 把每条伏笔的关键词列出来，数它在全文的出现次数
checks = {'F01 关键短语': '原文里的特征词', ...}
# 次数为 1 的要警惕：很可能是「只埋没收」
```
⚠️ **实测踩坑**：`银镯子` 只在第 6 章出现 1 次——埋了没回收。**埋点写完后必须回头补回收场景**，人工审校最容易漏这个。

## 四、写作流程（已验证）

```
立项（01-大纲/02-人物/03-设定）
  → 单批次细纲（含 BATCH-DECLARATION）
  → 逐章写：Write → fix_punct.py → check_wordcount.py → quality_check.py
  → 每章 P0 当场修掉
  → 全篇跑 quality_check + 完整性检查（dup/head）
  → 伏笔回收自检
  → 投稿材料打包
```

### 完整性检查（必跑，长篇同款）
```python
# 检查整篇重复、标题吞并首句
for each chapter:
    head = 首个非空行          # 必须是 `# 第N章　标题`
    body.count(首句) > 1      # 整篇重复
    len(head) > 25            # 标题吞并首句
```

### 合并稿标点终检（收尾必跑）

合并稿是**唯一交给平台的成品**，它的标点要单独再验一遍——逐章干净不等于合并干净
（合并时头部会写入元信息行）。

```python
t = open('06-全书合并稿.md', encoding='utf-8').read()
body = '\n'.join(t.split('\n')[6:])   # 剥掉头部元信息块（书名/字数/分隔线）
for pat in [',', r'\?', '!', ':', ';', '"', '\u300c', '\u300d']:
    assert not re.search(pat, body), pat
```

⚠️ **千分位逗号是预期例外，不要"修"它**。头部元信息行 `> 字数 19,669 字` 里的逗号
两侧是数字，`fix_punct.py` 的「两侧须有 CJK」规则本就跳过它——这是设计如此。
所以终检前必须先**剥掉头部元信息块**再看，否则会把这条正常逗号判成漏网之鱼。
正文里若出现千分位（如 `1,000` 文钱），同样会被跳过，也应保留。

**验收口径**（以本形态实测为准）：
- 逐章：`check_wordcount.py --all 04-正文` → 10/10 PASS
- 全篇：`quality_check.py .` → `P0 0 / P1 0 / P2 0`
- 合并稿正文：半角标点全为 0、直角引号 `「」` 为 0、弯引号 `“”` 左右配对等数

## 五、投稿材料清单

| 材料 | 内容 |
| --- | --- |
| 一句话简介 | 全书的钩子，用于简介栏 |
| 内容简介 | 200 字内 |
| 标签 | 3-5 个（`民俗` `规则怪谈` `短篇悬疑` `亲情`） |
| 作品亮点 | 3-5 条自荐语（给编辑看） |
| 章节清单 | 章名 + 字数 + 情绪 + 钩子形状 |
| **封面** | 600×800 jpg/png，< 5 MB —— 见下节 |
| 合规自查 | 尺度段落、AI 使用口径、版权登记 |

### 封面（投稿必备，实测工作流）

平台要求：**600×800 px（3:4）、jpg/png/jpeg、< 5 MB**。
封面要同时满足两个矛盾的约束：**有艺术性** + **缩略图里能看清书名**。

**核心做法：AI 出底图，文字用 Pillow 压上去。**

```
① ImageGen 出底图 → prompt 里必须写 "absolutely NO text, NO letters, NO watermark"
② Pillow: cover 裁切到 600×800 → 淡化平台水印 → 渐变压暗 → 绘标题/副题/署名 → 存 jpg+png
```

⚠️ **不要让 AI 把书名画进封面**。实测 AI 生成的中文封面字**必乱码**（看起来像字，实际
无法辨认），这是硬伤，不可接受。文字交给 Pillow 用本机字体绘制才可控、小图才锐利。

**排版规则（决定"能不能被点开"）**：

| 元素 | 位置 | 字体/色 |
| --- | --- | --- |
| 书名 | 上 1/2，**竖排** | `STXINGKA`（行楷）暗金 `#D8BA7A` + 暗色描边 |
| 主视觉 | 中下，重心偏左 | —— |
| 副题（题材词） | 主视觉下沿 | `STXIHEI` 暗金，字距手工撑开 |
| 署名 | 贴底，上方一道朱红短线 | `STSONG` 纸白 |

- **暗色描边是必需的**：±2-3 px 的多圈暗色文字，否则金字压在亮部会糊。
- **中段要加一层轻压暗**（约 `74/255`），把金字与主视觉分离；纯靠顶/底渐变不够。
- **投稿用户是"在信息流里扫缩略图"**，书名占画面上半部分才容易被一眼读到。

**踩坑清单**：
1. 平台水印在**右下角**（`AI生成 / WORKBUDDY`），AI 底图都带 → 局部高斯模糊 9 +
   与纯黑 blend 0.55 压暗；或构图时留裁切余地直接裁掉。
2. `cover` 裁切锚点用 `top = (nh-th) * 0.40`（略偏上），否则 3:4 会切掉桌面质感。
3. **排版必须"渲一次 → 读图 → 再调坐标"**，不能盲写。实测连撞两次版
   （标题压主体、副题压香头、副题盖署名），都是靠看图改出来的。
4. 本机中文字体：`STXINGKA`(行楷，最适合书名) / `STSONG`(宋体) / `STXIHEI`(细黑) /
   `STKAITI` / `STZHONGS`。
5. Pillow 装在隔离 venv：`~/.workbuddy/binaries/python/envs/default`。

## 六、⚠️ AI 合规（投稿前必读，会封号）

平台规则（2026 现行）：
- **纯 AI 生成：永久封禁**
- **AI 辅助：允许，但占比须 < 30%，且必须主动标注「AI 辅助创作」**
- 未标注被查出：**限流 30 天起**
- 部分工作室（如海狸故事）直接写明「**拒绝所有 AI 稿件，一经发现永不录用**」

**因此本引擎产出的稿件，交付时必须明确提示用户**：
1. 这是**辅助初稿**，发布前须人工通读并做**实质修改**（改词、改句、加自己的段落）
2. 使人工创作占比真实达标后，再按平台要求标注
3. 不要把"AI 生成"当卖点，也不要隐瞒

**广电监管边界**：AI 微短剧新规管的是**成片**（每集加 AI 标识）。**文字稿不在该环节**，所以写小说/剧本这条路本身不受限——但"像人写的"这一关必须过，这正是 `style-guide.md` 去 AI 腔部分的价值。
