# Phase 2: 卷内细纲

千章规模的核心原则：**只为当前批次写细纲**。批次（默认 10 章，范围 10-20）是细纲的最小生产单元。

## 1. 新卷开启（每卷一次）

1. 读 `00-总纲.md` 的卷级规划表，确认当前卷的主线推进目标、新要素、卷末大高潮方向。
2. 若规划表中该卷为"方向待定"，先根据前文实际进展（主线状态卡 + 近两卷卷摘要）补齐本卷方向，并回写总纲。
3. 检查 `03-伏笔账本.md`：所有"计划回收章"落在本卷的条目**强制**排入本卷细纲；已到期未回收的标红警报，最优先安排。
4. 在根 `01-写作计划.json` 的 `volumes` 中登记本卷（卷名/区间/status: in_progress）。
5. 新建 `vol-XX/` 目录，内含 `计划.json`（本卷全部章号 + pending）、`卷细纲.md`、`章节摘要.md`（空）。
6. 读 `references/guides/emotion-and-pacing.md`，设计本卷情绪曲线（每 3-5 章一个小爽点、卷末 1-2 章大高潮、泪点 ≤2 处）。

## 2. 批次细纲生成（每批次一次）

为本批次每章生成 **7 列规划** + 3 个补充字段：

| 列 | 内容 |
|----|------|
| 章号/标题 | 章号（4 位）+ 标题 2-6 字，有信息量或悬念 |
| 核心事件 | 本章推进了什么（必须服务主线或卷目标） |
| 关键场景 | 本章主要场景/舞台（1-2 个，防止场景漂移与重复） |
| 情绪标签 | 主情绪一个：爽/燃/泪/压/疑 + 副节拍一个（如"爽+燃"） |
| 钩子设计 | 章末悬念类型与内容（参考钩子十二式，类型不得连用 3 章） |
| 伏笔操作 | 埋设（登记 ID）/ 推进 / 兑现（账本 ID）/ 无 |
| 出场人物 | 本章角色列表（创作时按此提取人物卡） |

补充字段（每章一行，写在细纲表下方）：
- **小爽点位置**：本章的爽点/燃点/泪点具体是什么（每 3-5 章必须有一个明确兑现）
- **主线三问状态**：本章结束时"主角目标/阻碍/下一步"是否清晰，若模糊必须修正
- **力量体系检查**：本章是否有升级/战斗？是否符合力量体系规则？越级必须有铺垫

### 2.1 结构化声明块（新增，塌陷点一的修复）

细纲表下方**必须**额外写一个机器可读的声明块，格式固定：

```markdown
<!-- BATCH-DECLARATION
batch: 5
range: 45-54
forced_payoff: F56, F41, F07
planned_ops:
  45: plant:F61, advance:F45
  46: payoff:F20
emotion_curve: 45燃,46压,47秘辛,48压,49泪,50秘辛,51压,52燃,53压,54燃+泪
-->
```

**为什么必须结构化**：`quality_check.py` 的 `foreshadow` 检查会解析本块，
在批次末比对「声明的强制回收」与「账本中的实际动作」。

> ⚠️ **实测教训**：早期版本细纲只有自然语言的「强制回收伏笔」一行，
> 结果一部实战验证作品批次 4 声明 8 条、实际执行 4 条，执行率 50%，
> 且没有任何环节发现——因为没人拿细纲跟账本对过。结构化之后，
> 这条差异会在批次末被自动报成 P0。

**声明与执行不一致时的正确处理**（三选一，禁止静默跳过）：
1. 写作中确实偏离了计划 → **同步修改本声明块**，让声明反映实际
2. 发现计划外的伏笔该收 → 补进 `forced_payoff` 并说明原因
3. 确实没做到 → 改期到下一批次，写明顺延理由

细纲写入 `vol-XX/卷细纲.md`，只保留**当前批次**的细纲表与历史批次摘要；生成后向用户简报（批次范围 + 情绪曲线示意 + 本批次大事件 + 到期伏笔回收计划），用户确认后进入 Phase 3。连载模式下（总纲已确认过）可免确认直接续写。

## 3. 情绪曲线设计规则

- 一个批次内：压（危机/误解/失去）不超过连续 2 章，**压两章后必须爆**
- 每 3-5 章一个小爽点兑现；卷末 1-2 章是大高潮
- 大高潮前必须有铺垫章（收集/突破/集结），高潮后允许 1 章缓冲，然后立刻抛出新钩子进下一卷
- 泪点是稀缺资源：每卷最多 1-2 处，用在这里才值钱

## 4. 批次归档（每批次写完后执行）

1. 生成**批次摘要**（150 字：本批次推进了什么、发生了哪些变化），追加到 `卷细纲.md` 的批次摘要区。
2. 覆盖式更新 `卷细纲.md`：删除已完成批次的逐章细纲表，只留批次摘要 + 当前新批次细纲（防止该文件随卷增长）。
3. **在卷级 `vol-XX/计划.json` 补建下一批次的章节骨架**：为下一批次每一章追加
   `{chapterNo, title, status:"pending", wordCount:0, emotionTag:"", chapterFile}`，
   并把 `batch.current` 改为 `[起始章, 结束章]`、`batch.size` 改为本批次数。

   > ⚠️ **极易漏掉的一步**：`计划.json` 的 `chapters` 通常只登记到建档那一刻的章号。新批次开工前若不补建骨架，卷级 `completedChapters` 无法 +1、断点检测找不到下一章、整卷字数汇总也会少算新章。**批次细纲一旦生成，同一次操作里就把骨架补上**。

4. 更新根索引 `nextAction`（继续 / 细化下一批次）。

## 5. 卷末归档（每卷写完后执行）

1. 生成**卷摘要**（300-400 字：主线推进、人物关系变化、遗留伏笔、力量体系变动），写入 `vol-XX/卷摘要.md`。
2. 更新 `02-主线状态卡.md`（主角实力/资源/关系/所在地图/当前目标/卷进度）。
3. 更新 `04-设定词典.md`（本卷新增设定、等级变动）。
4. 核对 `03-伏笔账本.md`：本卷应回收条目全部结清；跨卷条目更新"计划回收"位置。
5. 更新根索引：本卷 `status: completed`，`nextAction` 置 `arc-planning`。
6. 若下一卷在总纲中"方向待定" → 结合当前走向更新卷级规划表（滚动规划：总纲是活文档）。
