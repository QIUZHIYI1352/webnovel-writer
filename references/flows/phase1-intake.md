# Phase 1: 创作立项

## 0. 初始化与断点检测

1. 检查当前工作目录及 `./webnovel/` 下是否存在未完成项目（根 `01-写作计划.json` 的 `nextAction != "done"`）。
   - 存在 → 进入**连载模式**：向用户报告进度（"《XXX》已更新至第 N 章，当前第 X 卷《卷名》还剩 M 章"），询问"继续更新"或开新书。确认继续后按 `nextAction` 分流：`arc-planning` → 执行 Phase 2 补细纲；`continue` → 直接进 Phase 3；`volume-archive` → 先执行卷末归档。
   - 不存在 → 新书流程。
2. 加载 `webnovel/user-preferences.json`（跨书共享），有偏好时在问答中排序常用项并标注"你的常用"。

## 1. 递进式问答

**Layer 1 — 核心定位（必答，3 问）**，每问支持 🎲随机 / 跳过：

- **Q1 题材与赛道**：玄幻 / 都市 / 仙侠 / 科幻 / 历史 / 悬疑 / 无限流 / 言情 / 🎲
- **Q2 主角与金手指**：主角的核心优势是什么（系统 / 重生 / 天赋 / 传承 / 异能 / 团队 / 无金手指纯流）？金手指要有**成长性**和**代价**，无代价的金手指会杀死张力。
- **Q3 核心爽点配方**：升级打脸 / 逆袭复仇 / 团队热血 / 悬疑反转 / 甜宠虐恋 / 种田经营 / 权谋博弈

**Layer 2 — 规格定制（可选 5 问）**：世界观核心规则、叙事视角（推荐第三人称限制视角）、情绪侧重（爽/燃/泪配比）、基调文风（热血爽直 / 冷峻 / 轻松幽默 / 细腻）、规模与节奏（几十万字试水 / 百万字长跑 / 不设上限连载；单卷默认 40 章，单批次默认 10 章）。

**Layer 3 — 标题与一句话卖点**：AI 生成 3-5 个候选书名，每个配一句"读者一句话记住它"的卖点。用户选择或自定义。

## 2. 总纲生成（00-总纲.md）

必须包含且按顺序：

1. **一句话故事**：{主角} 用 {金手指/能力} 在 {舞台} 追求 {主线目标}，对抗 {终极阻碍}。
2. **主线与终局**：主线目标具体可验证；终局允许后期演化，但立项时必须预设，防止写飘。
3. **力量体系 v1 规则**（长篇崩坏第一大源头，立项时定死）：
   - 等级阶梯名称 + 每级能力边界（能做什么/不能做什么）
   - 升级条件与代价（资源/机缘/风险）
   - 明确"禁区"：禁止出现的崩坏情形（无铺垫越级碾压、等级贬值、凭空能力）
4. **卷级规划表（v1，暂定）**：按当前预估规模列出 3-8 卷，每卷一行：卷名 / 主线推进目标 / 新要素引入（新地图、新对手、新配角）/ 卷末大高潮方向。后期卷允许"方向待定"，但至少规划到第 3 卷。
5. **黄金三章草案**：第 1/2/3 章各自的核心事件、情绪标签与钩子（详见 `references/guides/golden-three-chapters.md`），这是用户确认的重点。
6. **价值观底线**：一句话说明本书核心价值（努力/守护/复仇的代价/人性的复杂…），确保不歪。

## 3. 项目创建与确认

创建目录与文件（结构见 `references/flows/shared-infrastructure.md`）：

```
webnovel/{timestamp}-{书名}/
├── 01-写作计划.json      # 书级索引：书名/writingMode/volumes(第 1 卷 in_progress)/nextAction
├── 00-总纲.md            # 上述六项
├── 02-主线状态卡.md      # 初始版（主角初始实力/资源/关系/位置/目标）
├── 03-伏笔账本.md        # 空表（表头）
├── 04-设定词典.md        # 力量体系等级表 + 初始设定名词
├── 05-文风基准.md        # 空（第 1 章定稿后回填）
└── vol-01/
    ├── 计划.json         # 本卷章级状态：第 1 批次（默认前 10 章）pending
    ├── 卷细纲.md         # 空（Phase 2 填）
    └── 章节摘要.md       # 空
```

向用户展示确认卡片：一句话故事 / 题材基调 / 金手指 / 爽点配方 / 黄金三章草案 / 力量体系摘要 / 规模（卷数 × 单卷章数）。用户回复"确认"后进入 Phase 2。
