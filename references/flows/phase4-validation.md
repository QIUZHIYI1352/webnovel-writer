# Phase 4: 批次校验与修复（全自动）

每批次完成后、向用户汇报前执行。不合格章节自动重写，**最多 2 轮**；2 轮仍不合格的章节置 `status: "failed"` 并在汇报中单独说明。

## 1. 字数校验（客观）

```bash
python "<SKILL_DIR>/scripts/check_wordcount.py" --all "<项目>/vol-XX/"
```
- 低于 1700 字 → 扩充（补冲突/补细节/补对话潜台词，手法见 `references/guides/emotion-and-pacing.md`）
- 高于 2400 字 → 删水（优先删重复描写、静态说明、无信息量寒暄）

## 2. 钩子完整性

逐章检查章末：是否存在未解决张力（悬念/危机/期待）。判定标准：读者读完最后一句是否产生"下一章会怎样"的冲动。缺失 → 补写钩子段落；同时检查钩子类型是否与前两章连续重复，重复则改写类型。

## 3. 黄金三章复查（仅第 1-3 章，全书仅一次）

对照 `references/guides/golden-three-chapters.md` 检查：
- 第 1 章：前 300 字有冲突/异象？章末命运改变钩子？
- 第 2 章：金手指亮相并小试牛刀？主角目标说出口？
- 第 3 章：第一个爽点完整兑现（蓄力→反转→打脸→有见证者）？
不达标整章重写。

## 4. 力量体系一致性

- 本章能力表现是否在设定词典的等级边界内？
- 升级是否有代价/条件，且在前文有铺垫？
- 是否出现"无铺垫越级碾压"？出现 → 降级表现或补铺垫
- 设定名词是否全部在词典内（禁止同义新造，如"灵力/灵气"混用）？

## 5. 伏笔账本核对

- 细纲中计划兑现的条目是否真的在正文中兑现（**对照正文，不只看细纲**）？未兑现 → 要么补写，要么把状态改回"推进中"并重排回收计划。
- "计划回收章"已过期（超过埋设章 + 2 卷）的条目 → 标红，立即排入下一批次细纲。

## 6. 连贯性抽查

- 抽查本章开头与上一章末尾衔接（时间/地点/情绪是否连续）。
- 抽查出场人物言行是否符合人物卡（口头禅、说话风格、已知信息边界——角色不能说出他不该知道的事）。
- 抽查本章是否与 `章节摘要.md` 中已记录的事实矛盾。

## 7. 状态文件一致性

- 根 `01-写作计划.json` 的 `lastCompletedChapter`/`totalCompletedChapters` 是否与卷级 JSON 实际完成数一致？
- 卷级 JSON 每章 `wordCount` 是否与脚本实测一致？不一致以脚本为准修正。
- `nextAction` 是否反映了真实下一步（continue / arc-planning / volume-archive / done）？

## 8. 批次汇报格式

```
✅ 本批次第 N1-N2 章完成（第 X 卷《卷名》，累计 Y 章 / Z 万字）
章号 | 字数 | 情绪标签 | 钩子 | 伏笔操作
（逐章一行）
📖 主线进度：{一句话}
🎣 伏笔：本批次埋 X 条 / 收 Y 条 / 在账 Z 条（其中标红 W 条）
⚠️ 重写 M 章（原因）  或  全部一次通过
▶️ 下一步：{继续写第 N3 批次 / 进入第 X+1 卷《卷名》 / 本书完结}
```
