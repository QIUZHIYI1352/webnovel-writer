# Phase 0 手稿接入（把既有作品挂载到本引擎）

## 何时用

用户给出一个已有手稿目录，其结构与本 skill 标准结构不同（例如只有 `01-大纲.md` / `04-正文/` / `05-上章状态.md`），并要求"接着写""继续更新""帮我管起来""之后的你来写"。

手稿可能来自：早期版本的 skill、其他写作工具、或纯手工写作。

## 三条铁律

1. **只增不改**——绝不覆盖、移动、重命名用户原有文件。所有新档案都是**新增**。用户原有的大纲、正文、评审文档保持原样、原位置。
2. **实测优先**——章数、字数一律用脚本实测，**不采信文件名、元信息里的自报数字**。历史项目普遍存在"自报 2000 实为 1400"的问题。
3. **先档案化，后创作**——接入未完成前不写任何新章节。

## 步骤

### 1. 清点（只读）

列出目录全部文件与大小，归类为：规划类（大纲/人物/设定）、正文类、状态类、评分类、其他。

### 2. 正文本体盘点

```bash
python "<SKILL_DIR>/scripts/check_wordcount.py" --all "<项目>/" --json
```

产出：章数、逐章实测字数、均值、极差、不达标清单、命名格式（是否补零/是否含标题）。

**章号断档要单独列清单。** 断档常见于历史遗留（工具故障导致章节只写在对话里、从未落盘）。发现断档时提醒用户核实是否另有存稿，**不要默认跳过**——`codex-session-recovery` skill 可以从 Codex 会话记录中捞回从未落盘的正文。

### 3. 建立标准结构（全部新增）

**⚠️ 编号冲突处理（实测必遇）**：手稿根目录通常已存在 `01-大纲.md` / `02-人物.md` / `03-设定.md` / `05-上章状态.md`，与本引擎的 `01-写作计划.json` / `02-主线状态卡.md` / `03-伏笔账本.md` / `05-文风基准.md` **编号重名**。此时**不要**在根目录平铺，改用隔离目录：

```
<项目>/
├── （用户原有文件，一字不动）
├── 04-正文/                    ← 新章仍写这里，沿用用户命名习惯
└── _engine/
    ├── 01-写作计划.json
    ├── 02-主线状态卡.md
    ├── 03-伏笔账本.md
    ├── 04-设定词典.md
    ├── 05-文风基准.md
    └── vol-XX/
        ├── 计划.json
        ├── 卷细纲.md
        └── 章节摘要.md
```

- 卷 JSON 的 `chapterFile` 写相对路径：`../04-正文/第N章.md`
- 台账若用户已在 `03-设定.md` 里维护，**只增不改**地同步追加新条目（表下注明"由引擎补登，原表未改"），并在 `_engine/03-伏笔账本.md` 头部标注"两处同步"

映射规则：

| 旧文件 | → | 新档案 | 处理方式 |
|--------|---|--------|---------|
| `01-大纲.md` | → | `00-总纲.md` | 保留原文；**补「卷级规划表」**（卷号 / 章号区间 / 卷目标 / 卷末大事件 / 预期爽点 / 情绪曲线） |
| `02-人物.md` | → | `04-设定词典.md` 人物区 + `02-主线状态卡.md` | 人物条目分拆入词典；主角当前状态（实力/资源/关系/目标/处境）做成快照 |
| `03-设定.md` | → | `00-总纲.md` 力量体系段 + `04-设定词典.md` | 规则进总纲，名词进词典（附首现章） |
| `05-上章状态.md` | → | `02-主线状态卡.md` | 直接作为初始快照 |
| （通常没有） | → | `03-伏笔账本.md` | **从正文反推**，见步骤 5 |
| （通常没有） | → | `05-文风基准.md` | 从已有章节摘最佳段落 300-500 字 |
| `04-正文/` | → | `vol-XX/` | 见步骤 4 |

### 4. 建状态机

- 根 `01-写作计划.json`：书名、卷列表（range 按已写章数 + 总纲规划推断）、`lastCompletedChapter` = 已写最大章号、`totalCompletedChapters`、`nextAction`
  - 下一批次细纲缺失 → `arc-planning`；细纲齐备可续写 → `continue`；已写满整卷 → `volume-archive`
- `vol-XX/计划.json`：遍历正文文件，每章 `status: completed`、`wordCount` 填**脚本实测值**、`emotionTag` 未知的先留空并标注「待体检回填」
- **正文路径**：默认**不移动**用户文件。在卷 JSON 的 `chapterFile` 字段记录相对路径（可为 `../04-正文/第9章.md`），保证引擎找得到文件

### 5. 伏笔入账（接入里最值钱的一步）

通读正文 + 评分类文档，把"已在文中出现、尚未回收"的线索登记为 `F-XXX`：

- 字段：ID / 首现章 / 内容 / 埋设方式 / 计划回收章 / 状态
- **优先处理评审文档里点名的"未入账伏笔"**——这类线索风险最高，因为没有登记就等于不存在于系统记忆
- 按「最多跨 2 卷回收」的规则检查每条的计划回收章，超期标红

### 6. 补分层记忆

- `vol-XX/章节摘要.md`：为已有章节批量补摘要（150-250 字/章），从正文抽取
- `05-文风基准.md`：挑 3-5 段最能代表本书文风的原文（叙事 / 对话 / 动作各一），300-500 字
- `02-主线状态卡.md`：以最后一章末状态为准（若旧 `05-上章状态.md` 已是最新，直接采用）

### 7. 一致性体检

跑 Phase 5 六项检查（见 `phase5-review.md`），产出或合并 `06-评审.md`。

**P0 问题必须在开写新章前给用户确认处理方式**——否则新章会继承旧问题（例如"连续 N 章无爽点"如果是既成事实，新批次的第一要务就是补一次净收益）。

### 8. 汇报接入报告

给出：已有章数 / 总字数 / 不达标章清单 / 章号断档 / 已入账伏笔数与超期数 / P0 问题 / 建议下一步（改稿 or 直接续写）。

---

## 接入后：新章的位置

用户明确说了"之前的不用改"时，**新章仍写入原正文目录**（保持用户习惯的路径），不要强行搬到 `vol-XX/`。若用户希望统一，再执行搬迁并同步更新卷 JSON 的 `chapterFile`。

命名沿用用户既有习惯；若原命名会导致排序错乱（如 `第9章.md` / `第10章.md` 在部分工具下乱序），提出建议但**不擅自改名**。
