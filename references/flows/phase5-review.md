# Phase 5: 审稿模式（对既有稿件做体检）

用户说"评价一下这本""审一下这卷""看看有什么问题"时启用。**只读不改**，产出一份评审文档（`06-评审.md`），不擅自改正文。

## 0. 确定评审范围（先说实话）

1. 清点项目实际有的文件：正文目录里有哪些章？规划文件是否齐全？
2. **标出盲区**：缺正文的章（尤其第 1-3 章）无法评估开局，必须在评审文档开头写明覆盖范围。开局是网文生死线，缺它就不能下"这本书行不行"的结论。

## 1. 客观层（脚本先跑，别靠感觉）

```bash
python "<SKILL_DIR>/scripts/check_wordcount.py" --all "<项目>/04-正文/" --json
```
产出三组数据：均值 vs 目标字数、**波动区间**（波动极小如 ±2% 说明"写完场景就停"，而非按内容定长）、不合规章节清单。

## 2. 情绪序列（本项目最常出问题的项）

按章号列出情绪标签，看**序列形状**而不是单章质量：

- 是否连续 3 章以上只有"压"而没有兑现？→ P0 级问题（读者会疲）
- 主角在这 N 章里做过**有收益的主动决策**吗？全是付出 = 代入感崩塌，不管文笔多好
- 每卷第一个"爽/燃"兑现出现在第几章？距卷首超过 8 章要亮红灯

## 3. 钩子形状轮换（易漏）

逐章只取最后 3 行，判定形状（动作悬停 / 抉择悬停 / 信息炸 / 反差 / 登场 / 倒计时 / 追杀），然后看**形状序列**：

- 同一种形状连用 2 章以上 = 违反轮换纪律
- 高频陷阱：`动作做到一半停住`（推开/伸出手/张开嘴/没扣上）——单章都好，连用五章读者麻木
- 钩子三要素检查：期限 / 已启动的坏事 / 动作或对话；缺"已启动的坏事"就是靠模糊氛围吊人

## 4. 伏笔入账核对（对着正文，不对着细纲）

1. 逐章扫正文，把新出现的可疑线索列出来（物件、时间锚点、人物名、口语习惯、异常细节）。
2. 与台账逐条比对：**没登记 = 视为不存在**。漏登的高频类型：
   - 新出现的**时间锚点**（"十二年前也亮过一回"）
   - 新出现的**人物名**（只提过一次的路人）
   - **主角动作习惯被同化**（搁笔的姿势跟死者一样）——这类最容易被忽略却最关键
3. 反向检查：台账里标"本章回收"的，正文里真的兑现了吗？

## 5. 规则自洽（长篇第一崩坏源）

- 设定声明的规则，正文有没有违反或绕过？
- **效力边界**是否写死（例：销名只除"册上的字"，不除"人脑里的记得"）？没写死的地方，读者会追问，700 章就会失控
- 有横向分类、无纵向阶梯 → 升级感无从兑现
- 数字/名词反复出现（如"十二"出现四次）：是刻意暗线还是巧合？是暗线就明写，是巧合就改掉

## 6. 人物档案规格核对

对照 `references/flows/phase1-intake.md` 与人物档案要求，检查是否含**信息边界**字段（`已知` / `瞒着`）。缺这个字段，所有依赖信息差的伏笔都会在长篇里失效。

## 7. 评审文档结构（写入项目根目录 `06-评审.md`）

```
评审输入 / 评审盲区
一、客观数据（字数表 + 波动）
二、强项（先肯定真做得好的，具体到句）
三、硬伤（P0/P1/P2 分级，每条：现象 → 证据（章号/原句）→ 建议动作）
四、待确认（需要作者拍板的设定问题）
五、动手顺序（按优先级 1-2-3）
```

**纪律**：每条结论必须能指到具体章号或原句；不写"可以更精彩"这类无法执行的意见；不替作者改价值观与审美取向，只报事实与代价。
